## 0. AI 执行摘要（优先读取）

### 0.1 已确认的产品规则

1. 单个物理设备可以同时存在 USB ADB 与 Wi-Fi ADB；当前生效连接不可被另一条恢复的连接强制抢占。
2. 当前连接失效时，切换到另一条可用连接；新的当前状态持有旧连接作为 `nextState`。连接恢复后，仅作为备用。
3. ADB 连接状态与视频/相机的传输状态必须分离：ADB 断开不等于正在运行的流必须停止。
4. 只要 ADB 在线（无论 USB 或 Wi-Fi ADB），新建或仍可用的视频/相机流优先使用 `adb reverse`。
5. `adb reverse` 已失效、ADB 已断开、PC 收流服务与设备端推流服务仍存活时，设备端自动使用预先配置的 PC 局域网地址直连，继续同一个流会话。
6. ADB 恢复后，健康的直连流不强制切回 reverse；仅在直连失败、用户新开流或显式重连时重新选路。
7. 相机预览使用 4:3 低延迟 H.264：首选 `640x480 / 12~15fps / 600~900kbps`；仅在设备端同时支持相机输出与编码器输入时尝试 `800x600`。不使用 OpenCV 作主视频编解码。
8. 桌面预览保持原始屏幕纵横比；UI 可以用 4:3 容器留黑边，禁止强制裁切或拉伸成 4:3。
9. 文件浏览不做全盘 root 浏览；改为 App 上下文目录 + 少量常用公共目录。
10. MediaProjection 仍有效时，流传输恢复不得重建录屏；MediaProjection 已失效或从未授权时，记录原因并在设备端 Toast 提示重新授权。
11. PC 收流端口不固定：优先探测 6667（屏幕）与 6668（相机），不可绑定或 reverse 不可用时协商备用端口；设备端分别保存 reverse 端口与 PC direct 端口。
12. 文件浏览默认根目录为 `/sdcard`，只展示 ADB shell 实际可读的内容；应用列表额外显示最近安装的 3 个 debuggable App，点击直接进入该 App 的内置扩展存储目录。

### 0.2 不应采用的实现

| 禁止/不推荐 | 原因 | 替代 |
|---|---|---|
| `WiFiConnected => 永远 PC 直连` | 用户明确要求 ADB 在线时仍优先 reverse；Wi-Fi ADB 的 reverse 可用且更稳定。 | 传输状态独立决策，reverse 优先、直连仅失联接管。 |
| `DeviceConnectionState` 直接承载所有 socket 生命周期 | ADB 可用性与流 socket 健康度不一致；会导致“ADB 断开即停止流”。 | 新增独立 `StreamTransportState`。 |
| OpenCV `imencode(JPEG)` / `imdecode` 逐帧传流 | 无帧间压缩，带宽和 CPU 更高，延迟抖动更大；本仓库已有 H.264 链路。 | Android `MediaCodec` AVC 硬编，PC 端现有 JavaCV/FFmpeg 解码。 |
| 固定所有桌面画面为 `800x600` | 手机常见长屏；会裁切、变形或浪费编码面积。 | 保持源比例，限制最长边、帧率、码率；UI 留黑边。 |
| ADB 已断后再由 PC 下发“切到直连” | ADB 不存在时命令无法送达设备。 | 在 ADB 在线、启动流之前预下发 LAN host、端口、会话 token 与回退策略。 |
| LAN 收流端口无鉴权 | 局域网其他主机可占用端口或注入伪帧。 | 每个会话使用随机 token，握手后才接受帧。 |

### 0.3 必须实现的状态机

```text
DeviceConnectionState（已有/扩展）
  ADB_USB | ADB_WIFI | UNAUTHORIZED | DISCONNECTED

StreamTransportState（新增，独立）
  STOPPED
  REVERSE_ACTIVE(sessionId)
  DIRECT_ACTIVE(sessionId, pcHost)
  RECONNECTING(sessionId, candidates)
  FAILED(sessionId, reason)

核心迁移：
STOPPED --start+adbOnline--> REVERSE_ACTIVE
REVERSE_ACTIVE --reverseSocketFailure && directConfigReady && appAlive--> RECONNECTING
RECONNECTING --directHandshakeOk--> DIRECT_ACTIVE
DIRECT_ACTIVE --directFailure--> RECONNECTING
DIRECT_ACTIVE --adbRecovered--> DIRECT_ACTIVE（不抢占）
{REVERSE_ACTIVE,DIRECT_ACTIVE,RECONNECTING} --userStop/appStop--> STOPPED
```

### 3.2 服务端接口与中间件

没有云服务、HTTP API、DB 或 MQ 改动。本需求的“接口”是 PC 与 Android 设备端的本地 ADB command + TCP 二进制协议。

#### 3.2.1 ADB 配置 API（PC → Android）

所有 API 仅在 `device.canManageDevice == true` 时允许执行，目标必须始终使用 `device.adbTarget()`。

| API 名称 | 调用方 | 精确 ADB 命令形态 | 作用 | 幂等要求 |
|---|---|---|---|---|
| `configureStreamTransport` | PC `StreamSessionCoordinator` | `adb -s <target> shell am startservice -n <pkg>/com.newchar.debug.touch.ScreenRecordService -a com.newchar.debug.touch.action.CONFIGURE_STREAM_TRANSPORT --es stream_kind <screen\|camera> --es direct_host <pcIPv4> --ei direct_port <pcListenerPort> --ei reverse_port <deviceReversePort> --es session_token <base64url> --ez allow_direct_fallback true --ei protocol_version 2` | ADB 在线时预下发直连回退配置 | 同一 `session_token` 覆盖旧配置 |
| `setupReverse` | PC coordinator | `adb -s <target> reverse tcp:<deviceReversePort> tcp:<pcListenerPort>` | 新流首选 reverse；优先默认端口，失败时探测后续备用端口 | 已存在视为成功 |
| `removeReverse` | PC coordinator | `adb -s <target> reverse --remove tcp:<port>` | 流结束清理 | 不存在视为成功 |
| `stopStream` | PC coordinator | `adb -s <target> shell am startservice -n <component> -a <stopAction>` | 用户主动停止时使用；ADB 断开时不可依赖 | 允许重复 |

`<pkg>` 必须使用当前配置 `cameraAppPackage` 或当前设备端宿主包；不可硬编码为样例包。`session_token` 使用 `SecureRandom` 生成至少 128 bit，Base64 URL-safe 无 padding。

#### 3.2.2 TCP 协议 v2（设备 → PC）

所有端口为 TCP：屏幕 `6667`，相机 `6668`。PC listener 必须在下发配置和建立 reverse 前启动。

```text
ClientHelloV2（仅连接建立时发送一次，网络字节序）
  int32 magic                 // screen=0x4E435348, camera=0x4E434332
  int16 protocolVersion       // 2
  int8  streamKind            // 1=SCREEN, 2=CAMERA
  int8  transportKind         // 1=REVERSE, 2=DIRECT
  int16 tokenLength           // 固定 16 或 32
  byte[tokenLength] token

FrameV2（每帧）
  int32 magic
  int32 payloadLength         // 1..MAX_FRAME_BYTES
  int64 ptsUs
  int32 rotationDegrees       // screen 可为 0；保留统一布局
  int32 flags                 // bit0=codecConfig, bit1=keyFrame
  byte[payloadLength] avcAnnexB
```

PC server 处理规则：

1. `accept()` 后 2 秒内必须读完 `ClientHelloV2`；magic/version/streamKind/token 任一不符即关闭 socket。
2. 同一 `(physicalDeviceId, streamKind)` 仅允许一个 `sessionToken`；新 socket 合法时关闭旧 socket。
3. `codecConfig` 或首个 keyframe 到达前不向解码器提交普通帧。
4. 统计 `lastFrameAt`、`lastKeyFrameAt`、`transportKind`；不得用 ADB heartbeat 替代。
5. `DIRECT` listener 绑定 `0.0.0.0:<port>`；reverse socket 同样进入该 listener。

Android `H264StreamClient` 处理规则：

1. 保留 `reverseEndpoint = 127.0.0.1:<port>` 与 `directEndpoint = <configuredHost>:<port>`。
2. `REVERSE_ACTIVE` 的 socket 写失败后，先判断本地 `allowDirectFallback`；不依赖 PC 再发命令。
3. 直接尝试 `directEndpoint`，握手成功后为 `DIRECT_ACTIVE`；每次新连接先发送 codec config，并等待下一个 keyframe。
4. direct 连续失败按退避 `1s, 2s, 5s, 10s, max 30s`；不要在编码线程阻塞 connect。Android 端不能可靠观察 ADB 是否在线，reverse socket 写失败即作为可观测的接管触发条件。
5. ADB 恢复并不改变 `DIRECT_ACTIVE`；只有 `DIRECT` 写失败或收到新 session 配置才重新选择 reverse。

### 3.3 联调方案

| 阶段 | PC 行为 | Android 行为 | 成功判定 |
|---|---|---|---|
| A | 启动 server、生成 session、下发配置、建立 reverse | 保存 direct endpoint/token，连 reverse | 首帧 transport=`REVERSE` |
| B | 保持 server，不发送 stop | 人为断开 ADB，但保持前台服务和同一 LAN | 2 秒内收到 token 正确的 `DIRECT` 首帧；画面会话未关闭 |
| C | 恢复 ADB | 保持 direct socket 健康 | 不重启编码器、不强制切 reverse |
| D | 断开 direct 网络 | 触发重连；若 reverse 已恢复可选回 reverse | 显示重连中；恢复后首帧可解码 |
| E | 用户停止流 | 收到/尝试 stop；清理 PC listener | 无残留 socket/reverse/编码器 |

### 4.3 测试与验收

| 类别 | 用例 | 通过标准 |
|---|---|---|
| 状态单测 | Wi-Fi ADB 在线 + reverse 正常 | `REVERSE_ACTIVE`，绝不直接走 direct |
| 状态单测 | reverse 失败 + ADB offline + appAlive | reducer 进入 `RECONNECTING` 并允许 `DIRECT_ACTIVE` |
| 状态单测 | direct 健康 + ADB 恢复 | 保持 `DIRECT_ACTIVE` |
| 协议单测 | token 缺失、错误、旧 token | server 拒绝且不创建 decoder worker |
| 协议单测 | 新 direct socket 接管旧 reverse socket | 旧 socket 关闭；新流先收 codec config/keyframe |
| Android 设备测试 | 相机 640x480 / 800x600 | 不支持时自动降级；UI 显示实际 profile |
| 桌面预览 | USB 拔出后 Wi-Fi 接管 | 独立预览窗口不关闭；PNG/YUV/ADB H264 目标改为新 `adbTarget` |

### 4.4 性能基线

| 指标 | 目标 | 当前基线 | 风险 |
|---|---|---|---|
| 相机预览分辨率 | 默认 640x480，优先可用 4:3 | 当前 1280x720 | 机型无对应 Camera2 输出尺寸 |
| 相机帧率 | 12~15fps | 当前 30fps | 弱 Wi-Fi 抖动 |
| 相机码率 | 600~900kbps | 当前 2Mbps | 复杂场景块效应 |
| direct 接管时延 | 首帧 ≤2s（同 LAN） | 待测 | Doze、网络隔离、防火墙 |
| PC 解码 | 不新增 OpenCV；复用 JavaCV | 已有 H264FrameDecoder | JavaCV 包体已存在，避免重复依赖 |
| 内存 | 单流只保留最新可显示帧与有限缓冲 | 待测 | H264 pipe / decoder thread 泄漏 |

- 弱网策略：socket read timeout + 指数退避；直连不可达时保持 listener 与重连状态，避免频繁重启编码器。
- UI 策略：流切换时保留上次帧并覆盖“正在通过 Wi-Fi 接管…”，首个新关键帧后再清除提示。
- 不允许：在 EDT/Compose 主线程做 TCP connect、H264 decode、`adb pull` 或 `Process.waitFor`。

### 4.5 发版策略

- PC 与 Android 端仅支持 v2：设备端未实现 token hello 时，PC 关闭连接并提示升级设备端。
- 功能开关：`enableDirectStreamFallback` 默认关闭，白名单设备验证后开启。
- 先发布 Android v2，再发布 PC v2；PC 发现旧端不支持配置 action 或未收到 v2 hello 时，展示“设备端版本不支持推流，请升级”。
- 回滚：关闭 PC feature flag；不发送 `CONFIGURE_STREAM_TRANSPORT`；旧 reverse 流继续可用。

## 5. 风险识别

### 5.1 技术风险

| 风险 | 等级 | 规避/降级 |
|---|---|---|
| 设备不支持 800x600 或 AVC 该 profile | 高 | Camera2 + MediaCodec 探测；回退 640x480 或可用 4:3 尺寸 |
| PC 与手机不在可达 LAN / 防火墙阻断 | 高 | direct 失败提示；维持 reverse；ADB 也断时显示等待重连 |
| 直连 listener 被 LAN 非授权主机占用 | 高 | token hello、连接超时、每 session 单连接、日志脱敏 |
| USB/Wi-Fi 身份归并不稳定 | 高 | 引入物理设备 stable key；禁止仅以临时 ADB target 作为 session key |
| ADB 断开后 socket 重连丢 SPS/PPS | 高 | 每次连接先发送 codec config + keyframe；解码器等待关键帧 |
| PC/Android 两端升级不同步 | 中 | 仅 v2，关闭旧端连接并给出明确升级提示 |
| Camera2/MediaProjection 前台服务被系统杀死 | 中 | 正确 foreground service、停止原因上报、用户重开入口 |
| 直接保存 PC IP 或 token | 中 | PC IP 仅内存 session；token 永不落盘、不写普通日志 |

### 5.2 项目风险

- 涉及 `app_debug_pc_tools` 与 `lib_debug_touch` 两模块，必须同一分支联调。
- 设备端屏幕录制由 MediaProjection 驱动；若系统已撤销授权，网络接管无法恢复录制，只能提示用户重新授权。
- 真实网络环境必须覆盖企业 Wi-Fi、手机热点、VPN、访客网络；模拟器不足以验证 direct fallback。

### 5.3 合规与审核

- 不新增数据上云、第三方 SDK 或个人信息采集；但 LAN 直连会传输屏幕/相机画面，属于敏感内容处理。
- UI 必须仅在用户主动开始屏幕/相机预览后开启推流，显示“推流中”与显式停止入口。
- token、局域网 IP、视频帧不得写入常规日志；异常日志只保留错误类别与脱敏 session 前缀。
- Android 仍需按需处理 Camera、MediaProjection、前台服务通知；权限拒绝时不得尝试绕过。

## 6. 输入输出与数据规则

| # | 功能/接口 | 输入 | 输出 | 数据规则 | 待确认 |
|---|---|---|---|---|---|
| 1 | `DeviceInfo.adbTarget()` | 当前 `DeviceConnectionState` + USB serial/Wi-Fi endpoint | `serial` 或 `ip:port` | 仅用于 ADB 命令；不得作为物理设备 session key | 否 |

### 6.2 A/B 实验

不做用户增长 A/B。使用工程灰度开关：`enableDirectStreamFallback`，按设备白名单开启；比较 `stream_started` 成功率、接管耗时、崩溃和 decoder 错误率。

## 7. 待确认问题清单

1. ✅ MediaProjection 有效时自动继续同一录屏；权限不存在或已失效时，不尝试绕过授权，写入日志并 Toast 提示用户重新授权。
2. ✅ 统一下限为 `640x480/12fps/600kbps`，默认目标 `640x480/15fps/800kbps`。
3. ✅ 动态分配：优先 6667/6668；PC listener 绑定或 ADB reverse 失败时，选可用备用端口，并把 reverse 端口、direct 端口一同经配置 API 下发。
4. ✅ 兼容策略：忽略旧 Android 端。PC 仅接受 v2 hello/token；旧端 reverse 裸帧直接关闭，并展示“设备端版本不支持推流，请升级”。这里的“旧端”指设备端 App 尚未集成本次协议，不是 ADB 版本。
5. ✅ 文件根目录固定为 `/sdcard`，通过 ADB `ls` 展示可读内容；应用列表在右侧展示最近安装的 3 个 debuggable App，点击进入 `/sdcard/Android/data/<package>`。
