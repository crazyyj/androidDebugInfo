## 3. 待执行 — 真实设备联调验收（需要沟通）

> 以下为验证已编码功能的最终关卡；属「未执行」而非「代码缺口」。建议作为独立验收轮次执行。

**流媒体（doc1 §3.3 阶段 A–E）**
- A. 启动 server → 生成 session → 下发配置 → 建立 reverse；验证首帧 `transport=REVERSE`。
- B. 断开 ADB 但保前台服务与同 LAN；验证 2s 内收到 token 正确的 `DIRECT` 首帧，会话不关闭。
- C. 恢复 ADB；验证不重启编码器、不强制切 reverse。
- D. 断开 direct 网络；验证显示「重连中」，恢复后首帧可解码。
- E. 用户停止流；验证无残留 socket/reverse/编码器。

**waitState（doc2 §5.3）**
- 准备 v1 脚本验证行为完全不变。
- 准备 v2 脚本覆盖：UI 出现/消失、文本、selected、前台包名、前台 Activity、区域目标色占比。
- 每类条件验证：立即满足 / 延迟满足 / 始终不满足 / 暂停后恢复 / 执行中取消 / 状态命令超时。
- 构造回跳循环：单 wait step 前 10 次超时按策略执行、第 11 次强制停止；整脚本最多 100 步，第 101 步前停止。
- 校验 agent 回传 backend 为 `wait_state`；含 waitState 脚本不得出现 `adb_input`。
